# Aura 0.1.1-alpha

| Field       | Value                 |
| ----------- | --------------------- |
| **Version** | `0.1.1-alpha`         |
| **Date**    | 2026-07-28            |
| **Status**  | Published pre-release |
| **Tag**     | `v0.1.1-alpha`        |

This release extends the first public alpha with bounded async, I/O, HTTP,
FFI, package-consumption, and release-integrity work landed after
`v0.1.0-alpha`. It remains an alpha release: the support and language claims
below are intentionally limited to behavior covered by the current contract.

## Install

```bash
curl -fsSL https://aura.fadosoft.com/install.sh | AURA_VERSION=0.1.1-alpha bash
aura version
avm --list
```

The installer keeps versions isolated under `$AURA_HOME` (default:
`~/.aura/versions/<ver>/`) and activates the selected version through
`current`. Release artifacts target Linux amd64, macOS arm64, and macOS
amd64.

For a source install:

```bash
git clone https://github.com/auraspace/aura.git
cd aura
cargo install --path crates/aura-cli
aura version
```

Aura applications use the C backend and require a system C compiler at build
time. The CLI embeds the runtime and standard-library assets needed after a
binary install.

## Highlights

- General CFG lowering for bounded `await` shapes, including scalar, string,
  array, match, loop, and conditional control flow.
- Owned task outcomes and continuation cleanup across suspension, cancellation,
  and nested failure paths.
- Async I/O support for typed files, TCP streams, descriptors, and caller-owned
  handles.
- Typed HTTP handle accessors and lifetime management for request/response
  views.
- Extended FFI handle ownership, null checks, channel transfer, and explicit
  release support.
- Generic `HashMap`/`HashSet` collections with deterministic read-only
  snapshots and iterator coverage.
- Reproducible release archives, per-archive checksums, aggregate
  `SHA256SUMS`, release manifests, and mandatory minisign verification in the
  production workflow.

## Supported release targets

| Target                        | Build and acceptance                     |
| ----------------------------- | ---------------------------------------- |
| Linux x86_64 (`linux-amd64`)  | Native build and runtime smoke           |
| macOS arm64 (`darwin-arm64`)  | Native build and runtime smoke           |
| macOS x86_64 (`darwin-amd64`) | Cross-build and binary-format inspection |

Linux arm64 and Windows targets remain policy-only. They are not published
artifacts or support claims for this release.

## Release integrity

The tag workflow publishes an aggregate `SHA256SUMS` and detached minisign
signature. The GitHub Release job is attached to the `production` environment;
configure `AURA_MINISIGN_SECRET_KEY` as an environment secret and
`AURA_MINISIGN_PUBLIC_KEY` as the matching environment variable before tagging.
Missing or invalid signing material fails the release rather than producing an
unsigned success.

## Scope boundary

This alpha does not promise a stable language or runtime ABI. Live registry
publishing/authentication, `git=` and `github=` dependencies, workspaces,
generic package workspaces, true borrow/reference semantics, `Array` of
interfaces, LLVM, and Windows artifacts remain deferred. Async features outside
the bounded release contract may still be incomplete.

## Known limitations

- Applications built with `aura build` require a system C compiler on the build
  machine.
- The macOS amd64 artifact is cross-compiled and is not runtime-tested on the
  arm64 release runner.
- Offline registry fixtures prove receipt, checksum, rollback, and signature
  behavior; credentialed production registry publish/update remains open.
- A clean native host is required for each target's runtime acceptance. This
  checkout alone cannot claim Linux or macOS amd64 execution.
- See [`agents/debts.md`](../../agents/debts.md) for tracked technical debt.

## Verify the published release

```bash
bash scripts/release-acceptance.sh
git diff --check
```

The complete gate must pass on a host that permits local TCP fixture sockets.
After publication, verify the public installer and CDN copy:

```bash
bash scripts/release-acceptance.sh --network
```
