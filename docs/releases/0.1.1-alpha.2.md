# Aura 0.1.1-alpha.2

| Field       | Value             |
| ----------- | ----------------- |
| **Version** | `0.1.1-alpha.2`   |
| **Date**    | 2026-07-31        |
| **Status**  | Published release |
| **Tag**     | `v0.1.1-alpha.2`  |

This patch alpha release focuses on portability, registry acceptance, release
automation, the bounded async HTTP stack, and developer tooling. It continues
the experimental `0.1.1-alpha` support contract and is not a stable language or
runtime ABI release.

## Install

```bash
curl -fsSL https://aura.fadosoft.com/install.sh | AURA_VERSION=0.1.1-alpha.2 bash
aura version
avm --list
```

For a source install:

```bash
git clone --branch v0.1.1-alpha.2 https://github.com/auraspace/aura.git
cd aura
cargo install --path crates/aura-cli
aura version
```

Aura applications use the C backend and require a system C compiler at build
time. The CLI embeds the runtime and standard-library assets needed after a
binary install.

## Highlights

- Improved release automation by deriving `AURA_VERSION` from `Cargo.toml`,
  handling release tags consistently, and adding POSIX compatibility flags to
  C compilation scripts.
- Replaced platform-specific loopback handling with the shared
  `AURA_NET_LOOPBACK_ADDR` configuration used by network fixtures and tests.
- Updated registry acceptance coverage to exercise `aura-package` directly,
  including archive upload and response verification.
- Completed the bounded async HTTP handler stack and improved generated call
  expression emission and smoke-test health response validation.
- Added return-path analysis and diagnostics for non-unit functions that may
  fall through without returning a value.
- Added minimal `aura.toml` parsing and loading for package workflows.
- Expanded the Aura Language Support VS Code extension with project commands,
  CLI integration, updated build configuration, and language-server packaging.
- Refreshed site metadata, home-page content, documentation, and standard
  library details, including improved error handling.

## Supported release targets

| Target                        | Build and acceptance                     |
| ----------------------------- | ---------------------------------------- |
| Linux x86_64 (`linux-amd64`)  | Native build and runtime smoke           |
| macOS arm64 (`darwin-arm64`)  | Native build and runtime smoke           |
| macOS x86_64 (`darwin-amd64`) | Cross-build and binary-format inspection |

Linux arm64 and Windows targets remain policy-only. They are not published
artifacts or support claims for this alpha.

## Release integrity

The tag workflow publishes per-artifact checksums, an aggregate `SHA256SUMS`,
a release manifest, and a detached minisign signature. The GitHub Release job
requires the `production` environment with `AURA_MINISIGN_SECRET_KEY` and the
matching `AURA_MINISIGN_PUBLIC_KEY` configured before tagging.

Missing or invalid signing material fails the release instead of producing an
unsigned success.

## Known limitations

- Applications built with `aura build` require a system C compiler.
- This alpha does not promise a stable language or runtime ABI.
- Credentialed production registry publishing and update flows remain
  deferred; the acceptance coverage uses local fixtures.
- `git=` and `github=` dependencies, workspaces, true borrow/reference
  semantics, LLVM, and Windows artifacts remain out of scope.
- Async features outside the bounded release contract may still be incomplete.
- See [`agents/debts.md`](../../agents/debts.md) for tracked technical debt.
