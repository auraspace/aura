# Aura 0.1.1-alpha.1

| Field       | Value             |
| ----------- | ----------------- |
| **Version** | `0.1.1-alpha.1`   |
| **Date**    | 2026-07-29        |
| **Status**  | Published release |
| **Tag**     | `v0.1.1-alpha.1`  |

This is a follow-up alpha release focused on collection iteration, language
server and formatter tooling, class semantics, async memory handling, and
release verification. It continues the experimental `0.1.1-alpha` support
contract and is not a stable language or runtime ABI release.

## Install

```bash
curl -fsSL https://aura.pilotworks.dev/install.sh | AURA_VERSION=0.1.1-alpha.1 bash
aura version
avm --list
```

For a source install:

```bash
git clone --branch v0.1.1-alpha.1 https://github.com/auraspace/aura.git
cd aura
cargo install --path crates/aura-cli
aura version
```

Aura applications use the C backend and require a system C compiler at build
time. The CLI embeds the runtime and standard-library assets needed after a
binary install.

## Highlights

- Added invalidation-checked live collection iterators and key-based mutation
  handles for collection entries.
- Improved class inheritance, visibility checks, constructor argument
  validation, and package-qualified class lookup.
- Completed the language server MVP with richer completion, documentation,
  formatting, diagnostics, navigation, and rename support.
- Added formatter support for `.aura` files and directories, including a
  `--check` mode for CI and release gates.
- Improved async function memory allocation and string ownership handling in
  generated code.
- Added the bounded Aura-level async HTTP/1.1 server example, typed request /
  response bridge, graceful shutdown fixture, and monotonic `std.time.sleep`
  timer lowering. TLS, HTTP/2/3, WebSockets, compression, multipart, and
  HTTP client APIs remain deferred capability-gated work.
- Added `std.task.joinTask` and `std.task.cancelTask` wrappers, with generic
  task-handle payload inference covered by the compiler and corpus.
- Improved macOS version-manager symlink handling and refreshed language-tour,
  syntax, enum, result, and testing documentation.

## Supported release targets

| Target                        | Build and acceptance                     |
| ----------------------------- | ---------------------------------------- |
| Linux x86_64 (`linux-amd64`)  | Native build and runtime smoke           |
| macOS arm64 (`darwin-arm64`)  | Native build and runtime smoke           |
| macOS x86_64 (`darwin-amd64`) | Cross-build and binary-format inspection |

Linux arm64 and Windows targets remain policy-only. They are not published
artifacts or support claims for this alpha.

## Release integrity

The tag workflow publishes per-artifact checksums, an aggregate `SHA256SUMS`,
a release manifest, and a detached minisign signature. The GitHub Release job
requires the `production` environment with `AURA_MINISIGN_SECRET_KEY` and the
matching `AURA_MINISIGN_PUBLIC_KEY` configured before tagging.

Missing or invalid signing material fails the release instead of producing an
unsigned success.

## Verification

The release acceptance gate covers:

- Workspace tests and Clippy with warnings denied.
- Corpus and compiler regression checks.
- Sanitizer smoke tests and local installer smoke tests.
- Native macOS arm64 package execution.
- Cross-file validation of the macOS x86_64 package.

The Linux native artifact still requires the Linux GitHub Actions runner for
its native runtime acceptance. The macOS x86_64 artifact is inspected as a
Mach-O x86_64 binary and is not executed on the arm64 runner.

## Known limitations

- Applications built with `aura build` require a system C compiler.
- This alpha does not promise a stable language or runtime ABI.
- Live credentialed registry publishing and update flows remain deferred.
- `git=` and `github=` dependencies, workspaces, true borrow/reference
  semantics, LLVM, and Windows artifacts remain out of scope.
- See [`agents/debts.md`](../../agents/debts.md) for tracked technical debt.

